# Phase 2 Goal: Standalone Machine Learning Inference Microservice

**Phase ID:** `phase-2-ml-service`  
**Status:** Completed  
**Prerequisites:** Phase 0 (Baseline Setup)  

---

## 1. Objective
Develop an isolated, highly-explainable Machine Learning microservice in Python using FastAPI/Flask and Scikit-Learn principles. The service ingests patient symptoms, transforms them into multi-hot feature vectors, and runs inference against a trained probabilistic classifier to output the primary condition and top-3 differential diagnoses with calibrated confidence percentages.

---

## 2. Scope & Deliverables

### In Scope
- **Dataset & Preprocessing:**
  - Kaggle Disease Prediction dataset (~130 symptoms, ~40 distinct conditions).
  - Preprocessing and generator script that normalizes symptom names and generates multi-hot binary vectors.
- **Model Training & Evaluation:**
  - Train an interpretable probabilistic classifier (`SymptomDiseaseClassifier`).
  - Compute performance metrics (Accuracy $\ge 90\%$, 99.69% achieved).
  - Export model artifacts: `model.pkl`, `symptoms.json` (feature ordering), `features.json`, and `diseases.json`.
- **Inference Microservice (`ml-service/`):**
  - Standalone service listening on port 8000.
  - Endpoints:
    - `GET /health`: Model status, memory usage, feature count.
    - `GET /symptoms`: Returns the complete ordered list of 130+ supported symptom keys for the UI selector.
    - `POST /predict`: Ingests `{ "symptoms": ["cough", "fever"] }` and returns top 3 predictions with confidence scores using `predict_proba()`.
- **Testing:**
  - Automated test suite with `pytest` (`tests/test_predict.py`) covering standard symptoms, unknown symptoms, and empty payloads (100% pass rate).

### Out of Scope
- Direct public user traffic (all external requests must be proxied through the Node.js API Gateway).
- Deep learning neural networks (unnecessary complexity for tabular multi-hot classification).

---

## 3. Technical Specification & API Contract

### 3.1 Inference Endpoint (`POST /predict`)

- **URL:** `http://localhost:8000/predict`
- **Request Body:**
  ```json
  {
    "symptoms": ["chills", "high_fever", "cough", "fatigue"]
  }
  ```
- **Response (200 OK):**
  ```json
  {
    "success": true,
    "primary_condition": "Common Cold",
    "confidence": 84.5,
    "top_predictions": [
      { "disease": "Common Cold", "confidence": 84.5 },
      { "disease": "Pneumonia", "confidence": 10.2 },
      { "disease": "Bronchial Asthma", "confidence": 3.8 }
    ],
    "disclaimer": "This prediction is generated by an AI classifier for supportive triage only. It is not a clinical medical diagnosis."
  }
  ```

### 3.2 Error & Boundary Handling
- **Unknown Symptoms:** Stripped out gracefully with a non-fatal warning in the response; remaining valid symptoms are evaluated.
- **Zero Matched Symptoms:** Returns HTTP 422 with message: `"No valid recognized symptoms provided in request"`.
- **Malformed JSON:** Handled with HTTP 422.
